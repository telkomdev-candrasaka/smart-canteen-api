# Smart Canteen API

Backend API untuk sistem pemesanan multi-tenant open space. Service ini menangani autentikasi pengguna, pengelolaan tenant dan menu, pembuatan order, single checkout lintas tenant, pembayaran mock, serta notifikasi order real-time berbasis Redis dan Server-Sent Events (SSE).

## Overview

Repository ini adalah backend Node.js/Express dengan MongoDB sebagai database utama. Harga order selalu dihitung dari data menu di database, bukan dari harga yang dikirim client. Untuk alur event, pembayaran yang berhasil akan mem-publish event Redis dan tenant dapat berlangganan update order melalui endpoint SSE.

## Features

- Registrasi dan login user dengan JWT
- Penyimpanan user dengan role `SUPER_ADMIN`, `TENANT_ADMIN`, dan `MEMBER`
- Pembuatan tenant beserta embedded menu items
- Daftar tenant, detail tenant, dan daftar menu per tenant
- Pembuatan order single-tenant dengan perhitungan harga dari menu database
- Single checkout lintas tenant melalui resource transaction
- Mock payment yang menandai order sebagai `paid`
- Redis publish untuk event `ORDER_PAID`
- Tenant-specific order stream via SSE
- Validasi request untuk auth, tenant, order, item, dan payment
- Test suite Jest dengan coverage threshold global 95%

## Tech Stack

- **Runtime:** Node.js
- **Web framework:** Express
- **Database:** MongoDB + Mongoose
- **Authentication:** JWT (`jsonwebtoken`)
- **Password hashing:** `bcryptjs`
- **Realtime/eventing:** Redis (`ioredis`) + Server-Sent Events
- **Testing:** Jest, Supertest, mongodb-memory-server

## Architecture

High-level flow:

```text
Client
  -> Express Routes
  -> Validators / Middleware
  -> Controllers
  -> Models
  -> MongoDB

Payment success
  -> Redis publish (tenant:{tenantId}:orders)
  -> SSE stream (/tenants/:id/orders/stream)
```

Beberapa keputusan desain yang terlihat dari implementasi saat ini:

- Menu disimpan sebagai embedded subdocument di dalam tenant
- Order hanya berlaku untuk satu tenant
- Transaction menggabungkan beberapa order dari tenant berbeda dalam satu checkout
- Payment tidak terhubung ke gateway eksternal; status sukses diproses secara mock
- Kegagalan publish Redis tidak membatalkan response payment

## Prerequisites

- Node.js terpasang di mesin lokal
- MongoDB yang bisa diakses aplikasi
- Redis untuk alur runtime event publishing dan SSE realtime

> Catatan: test suite tidak membutuhkan Redis sungguhan karena memakai mock dari `_mocks/ioredis.js`.

## Environment Variables

Buat file `.env` di root project.

```env
PORT=3000
MONGODB_URI=mongodb://localhost:27017/smart-canteen
JWT_SECRET=replace-with-a-secure-secret
REDIS_URL=redis://localhost:6379
```

| Variable | Required | Purpose |
|---|---:|---|
| `PORT` | No | Port HTTP server. Default `3000`. |
| `MONGODB_URI` | Yes | Koneksi database MongoDB. |
| `JWT_SECRET` | Yes | Secret untuk sign dan verify JWT. |
| `REDIS_URL` | Yes untuk event runtime | Koneksi Redis untuk publish event payment dan subscribe SSE tenant. |

## Getting Started

### 1. Install dependencies

```bash
npm install
```

### 2. Configure environment

Buat file `.env` seperti contoh di atas.

### 3. Seed sample data

```bash
npm run seed
```

Seeder akan membuat sample tenant beserta menu. Seeder mengecek nama tenant yang sudah ada, jadi tenant dengan nama yang sama tidak akan dibuat ulang.

### 4. Run the API

```bash
npm start
```

Server akan berjalan di `http://localhost:3000` jika `PORT` tidak diubah.

|---|---|---|

| `GET` | `/transactions/:id` | Mengambil detail transaction |

## Authentication

Auth API saat ini menyediakan dua endpoint:

- `POST /auth/register`
- `POST /auth/login`

Token JWT di-sign menggunakan `JWT_SECRET` dan payload token berisi:

- `id`
- `email`
- `role`
- `tenantId`

Repository juga memiliki middleware `verifyToken` dan `requireRole`, tetapi route protection belum dipasang ke route resources yang ada saat ini. Jadi README ini hanya mendokumentasikan helper auth yang benar-benar tersedia di codebase, tanpa mengklaim enforcement RBAC di seluruh endpoint.

## Example Requests

### Register user

```bash
curl -X POST http://localhost:3000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"secret123","role":"SUPER_ADMIN"}'
```

### Login user

```bash
curl -X POST http://localhost:3000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"secret123"}'
```

### Create tenant with menu

```bash
curl -X POST http://localhost:3000/tenants \
  -H "Content-Type: application/json" \
  -d '{
    "name":"Kopi Sudut",
    "description":"Coffee corner",
    "menu":[
      {"name":"Americano","price":18000},
      {"name":"Croissant","price":20000}
    ]
  }'
```

### Create single-tenant order

```bash
curl -X POST http://localhost:3000/orders \
  -H "Content-Type: application/json" \
  -d '{
    "tenantId":"<tenantId>",
    "items":[
      {"menuItemId":"<menuItemId>","name":"Americano","price":1,"quantity":2}
    ]
  }'
```

> Implementasi akan mengabaikan harga dari client dan menghitung total menggunakan harga menu dari database.

### Create transaction (single checkout lintas tenant)

```bash
curl -X POST http://localhost:3000/transactions \
  -H "Content-Type: application/json" \
  -d '{
    "customerName":"John",
    "customerPhone":"08123456789",
    "tableNumber":"A1",
    "items":[
      {"tenantId":"<tenantId>","menuItemId":"<menuItemId>","name":"Americano","quantity":2}
    ]
  }'
```

### Process payment

```bash
curl -X POST http://localhost:3000/payments \
  -H "Content-Type: application/json" \
  -d '{"orderId":"<orderId>","method":"manual"}'
```

### Subscribe to tenant order stream

```bash
curl -N http://localhost:3000/tenants/<tenantId>/orders/stream
```

Event yang dipublish saat payment berhasil berbentuk JSON string, misalnya:

```json
{
  "event": "ORDER_PAID",
  "order": {
    "_id": "...",
    "tenantId": "...",
    "status": "paid"
  }
}
```

## Data Model Notes

- **Tenant** menyimpan `name`, `description`, dan `menu[]`
- **Menu item** memiliki `name`, `description`, `price`, dan `available`
- **Order** menyimpan `tenantId`, `items[]`, `total`, dan `status`
- **Transaction** menyimpan `customerName`, `customerPhone`, `tableNumber`, kumpulan `orders`, `grandTotal`, dan `paymentStatus`
- **User** menyimpan `email`, hashed `password`, `role`, dan optional `tenantId`

## Realtime Event Flow

Saat `POST /payments` sukses:

1. Order di-update menjadi `paid`
2. Backend publish event ke Redis channel `tenant:<tenantId>:orders`
3. Client yang subscribe ke `GET /tenants/:id/orders/stream` menerima event melalui SSE

Kalau publish Redis gagal, request payment tetap sukses dan error hanya di-log ke console.

## Known Constraints

- Payment flow masih mock; belum terhubung ke payment gateway eksternal
- Route resources saat ini belum diproteksi middleware auth/RBAC
- SSE butuh Redis yang aktif untuk alur runtime normal
- Menu masih embedded di dokumen tenant, cocok untuk skenario ringan hingga menengah
